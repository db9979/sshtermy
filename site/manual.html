Manual

Everything important about sshTermy in one place. For printing there is the quick reference (PDF); every key can also be looked up in the app with F1.

Getting started

  1. Install – see Install. sshTermy is a single file for Windows, macOS and Linux.
  2. Create a master password. On first start you choose a password for the encrypted store (Argon2id + AES-256-GCM). It is never saved. On Windows your Windows sign-in can unlock it as well (DPAPI).
  3. Bring your connections: i in the manager imports from ~/.ssh/config, PuTTY, MobaXterm, Ansible inventories or CSV. Or press n for a new connection.
  4. Set up AI (optional): s in the manager. Pick a provider (your own server, Ollama, OpenAI, Claude); Ctrl+T tests it.
  5. Connect: pick a connection, ⏎. F10 takes you back to the manager while the session keeps running.

Almost everything is in the command palette Ctrl+Space: type what you are looking for, e.g. “lock”, “audit” or “matrix”.

Connections

The form (n/e) shows only name, address, user and sign-in at the top; “Advanced” opens jump host, tags, folder, device type, shortcut and more.

  • Sign-in: password (encrypted in the store or in the system keychain), key file (PuTTY .ppk too), SSH agent, security key (FIDO), certificates. c in the manager creates a key and copies it to the server.
  • Folders and tags: o creates folders (“Customer / Site” nests), drag with the mouse to reorder. #tag in the search filters.
  • Jump host: connect through another server; sshTermy remembers which jump host fits which network.
  • Telnet, serial, local: “Connection type” picks Telnet, a USB console cable or this computer's shell (Alt+L).
  • Persistent session: always land in the same tmux/screen session for a connection, even from another computer.

Terminal and tabs

  • F7/F8 switch tabs, Alt+T lists them all, Alt+N/Alt+W open and close.
  • Ctrl+T splits the view (2 to 6 panes), Alt+I types into all visible panes at once.
  • ⇧F10 moves a tab into its own terminal window.
  • Ctrl+F searches the scrollback, Ctrl+E jumps to error lines.
  • F9 and ⇧F1…⇧F8: quick commands, preset for the device (Linux, Windows, Aruba, Cisco, Juniper, MikroTik, FortiGate …).
  • F6 host overview: CPU, RAM, disk, updates on servers, live graphs on Linux (t 5 min / 1 h, z large); firmware, ports and VLANs on network devices; c containers.
  • If the line drops (Wi-Fi, VPN, standby), sshTermy reconnects by itself, restarts tunnels and re-attaches tmux/screen. After waking up or a network change all connections are checked right away.

AI copilot

  • Ghost text: a grey suggestion while you type, Tab or → accepts.
  • Next commands: up to four suggestions after every command, Alt+1…4 inserts (without Enter).
  • Why? & fix: when a command fails, Alt+0 explains the cause and suggests a fix.
  • Ask AI: F3; the answer knows the screen, the system and your previous commands.
  • Fallback providers: if the first one fails, the next takes over (Settings › AI).
  • Learning per device: correct an AI command and sshTermy remembers it for that device.

Goal, agent and plan mode

F2 opens goal mode: describe a goal (“set up nginx with TLS”), the AI proposes one command per step, you confirm with ⏎. Tab switches to agent mode:

LevelWhat runs without asking
Carefulread-only commands only
Normaleverything except dangerous commands, sudo and inline code
Fulleverything except dangerous commands
Plan firstthe AI presents a plan, you edit and approve it

Dangerous commands (e.g. rm -rf, formatting, switch reload) never run automatically. Successful goals can be saved as a runbook and later run on many hosts.

Switches, routers, firewalls

sshTermy recognises ArubaOS-Switch/ProCurve, ArubaOS-CX, Cisco IOS, Juniper Junos, MikroTik RouterOS, FortiGate, Comware and Huawei. On these devices there are never hidden exec channels: every query runs visibly at the prompt.

  • F6 → r: firmware, model, CPU/RAM, ports and VLANs.
  • F6 → b: back up the configuration encrypted (show running-config, Junos show configuration | display set, RouterOS /export, FortiOS show full-configuration); d shows the diff to the previous one.
  • Config rules: e.g. “ntp server must be set”; violations show up after every backup.
  • Find a device: enter a MAC or IP, sshTermy asks all switches for their MAC, ARP and LLDP tables and names switch and port.
  • Schedule (z): e.g. a nightly backup of all switches in a folder.

Many hosts

  • Broadcast (m): commands or a runbook on many hosts at once; one tile per host (green done, red failed, pulsing while running), danger check first.
  • Network scan (f): finds SSH hosts in a network and adds them as connections.
  • Workspaces (w): save split views; g opens a folder as a grid.
  • sshTermy is tested with 1000 connections: manager, search, palette and sync stay within a few milliseconds per frame.

Files and tunnels

  • F5: two-sided SFTP, copy with c or by dragging, e opens a server file in your own editor and uploads it on save.
  • tsz/trz in the terminal transfer files even through jump hosts (trzsz).
  • F4: switch tunnels (local, remote, SOCKS) on and off; web services open in the browser.

Security

  • Store: all passwords, keys and API keys encrypted; unreadable without the master password.
  • Danger check: on production hosts (or everywhere) risky commands need a second confirmation, also when pasted; hold ⏎ until the bar is full or press y.
  • Lock: immediately or after idle time; sessions keep running behind it.
  • Audit log (Settings › Security): who did what on which host and when. Every line is chained and signed; “Verify and save audit log” reports changed, deleted or reordered lines. Commands with a leading space appear only as “(private)”.
  • Updates are signed with Ed25519; an update without a valid signature is rejected.

AI privacy

Before anything is sent, sshTermy removes passwords, keys and tokens. Under Settings › AI › “AI privacy” you choose:

  • all providers – the default.
  • local AI only – only endpoints in your own network (localhost, private IPs, .local/.lan/.internal); cloud providers are skipped.
  • AI off – nothing leaves the computer.

Per connection the tags ki-lokal and ki-aus apply, e.g. for customer networks; the stricter setting wins. “Show last AI request” shows exactly what was last sent to which host and model.

Sync and team

  • Sync (y): connections, tunnels, runbooks and settings end-to-end encrypted through a cloud folder (OneDrive, Dropbox, iCloud, Syncthing) or WebDAV (NAS, Nextcloud).
  • Team package: share a folder encrypted as .sshteam; team folders can be subscribed to and stay current.
  • Share: show a tab live; viewers watch along and type only if you allow it.
  • Relay: reach servers behind NAT/firewalls through your own relay.

Backup and moving to a new computer

Settings › Import / export › “Save full backup” (or sshtermy backup) packs the whole data folder into a .sshtbak file encrypted with the master password: connections, keys, logs, switch backups, known_hosts and settings.

On the new computer: install sshTermy, create any password on first start, then “Restore full backup” (or sshtermy restore file.sshtbak). After confirming, sshTermy restarts and uses the old master password. The previous state stays next to it as ….vorher-<date>.

MCP for AI clients

Claude Desktop, Claude Code and other MCP clients can use sshTermy as a tool. Switch it on under Settings › Security › “MCP access for AI clients”:

  • read only: list connections and tabs, read a tab, run read-only commands (df -h, show interfaces).
  • with confirmation: any other command runs only after y in sshTermy.
claude mcp add sshtermy -- sshtermy mcp

Claude Desktop: add the server {"command": "sshtermy", "args": ["mcp"]} to claude_desktop_config.json. sshTermy must be running and unlocked. AI privacy applies here too, and every call is in the audit log.

Reporting bugs

  1. Turn on Settings › “Debug log for bug reports” (or start sshtermy --debug).
  2. Reproduce the problem.
  3. Help › “Save cleaned debug log”: a copy without hosts, IPs, user names and passwords lands in Downloads.
  4. Open an issue on GitHub and attach the file.

If sshTermy crashes, it offers a cleaned crash report on the next start.

FAQ

I forgot my master password.

Without the password the store cannot be decrypted; that is on purpose. On Windows the Windows sign-in (DPAPI) helps if it is switched on. Otherwise rename the data folder and start over; synced connections come back with the sync password.

Windows says “Windows protected your PC”.

The .exe is not code-signed yet. “More info” → “Run anyway”. With winget the warning usually does not appear.

macOS says the app “cannot be opened”.

Install through Homebrew or the one-liner, or remove the quarantine flag: xattr -d com.apple.quarantine sshtermy_darwin_arm64.

Where is my data?

Windows %APPDATA%\sshtermy, macOS ~/Library/Application Support/sshtermy, Linux ~/.config/sshtermy. SSHTERMY_HOME moves the folder, e.g. to a USB stick.

The connection to an Aruba switch drops immediately.

Some switches end the session when a second channel opens. sshTermy recognises network devices and opens only the shell there. If it does not: set the device type to “Network device” under “Advanced” in the form.

The function keys do nothing.

Some terminals or laptops grab F keys (e.g. for brightness). Hold the Fn key or remap keys under b in the manager. On the uConsole, Fn+1…= are F1…F12.

The AI does not answer.

The dot at the top right shows the status. s → Ctrl+T tests the endpoint. If AI privacy is set to “local AI only” or “AI off”, or the connection has the tag ki-aus, that is intended.

Are my commands sent anywhere?

Only to the AI provider you set up, and only cleaned. sshTermy has no telemetry. The update check only asks GitHub for the latest version.

Can I use sshTermy without AI?

Yes. Without a provider (or with “AI off”) it is a complete SSH terminal with manager, SFTP, tunnels, broadcast and backups.

How do I get updates?

sshTermy checks on start and shows new versions; F12 → u installs. With Homebrew, apt or winget updates come through the package manager.
